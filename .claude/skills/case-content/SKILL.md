# 導入事例コンテンツ制作スキル（デジタルワークス共通基盤）

導入事例を「事例毎のプロジェクトフォルダ」で管理し、
**素材の蓄積（inbox）→ 正本化（case.md）→ 媒体別アウトプット（outputs/）** の
一方向フローで運用する。事例に関する作業は必ずこのスキルに従うこと。

## 大原則

1. **正本は `case.md`** — すべてのアウトプットは case.md から書き起こす。
   アウトプット側だけを直すことは禁止（直すなら先に正本を直す）。
2. **このリポジトリは public** — `inbox/` に置いた瞬間から公開される。
   掲載許諾前の実名・商談情報・未公開価格は匿名化してからコミットする。
   許諾ステータス（case.md のメタ情報）に反する表記を一切書かない。
3. **事実性** — 数値・成果は素材（inbox の出典）に基づく。誇大表現・
   未計測の実績値・架空の声を書かない（lp-create スキルの共通ルール 7 と同じ）。
4. **一覧の三点更新** — 事例の追加・変更時は次の 3 つを必ず揃えて更新する:
   `cases/README.md` の一覧表（人が読む正本）、`cases/index.html`（カタログ）、
   `cases/index.json`（検索用インデックス。タグ・成果・Board 案件番号を持つ）。
   「◯◯な事例を探して」と依頼されたら index.json のタグ・results から検索する。

## ディレクトリ構造（正）

```
cases/
├── README.md                   # 事例一覧の正本 + 運用ルール
├── index.html                  # 事例カタログ（GitHub Pages で公開される一覧）
├── index.json                  # 検索用インデックス（タグ・成果・Board 案件番号）
├── _template/                  # 新規事例の雛形（case.md / inbox/README.md）
└── cNNN-<slug>/                # 事例プロジェクトフォルダ
    ├── case.md                 # 事例の正本
    ├── inbox/                  # 生素材（YYYYMMDD-<内容>.md 形式で随時追加）
    ├── assets/                 # 画像（ロゴ・写真・グラフ）
    └── outputs/
        ├── web/index.html      # Web 用事例詳細ページ（自己完結 HTML）
        ├── lp-embed/<name>.html # LP に貼る HTML 断片
        └── slides/             # セールス資料（.pptx / .pdf）
```

命名: `cNNN` は全プロダクト通しの連番（c001, c002, …）。
`<slug>` は英小文字ケバブケース。実名許諾済なら社名由来、それ以外は
業種由来（例: `c001-manufacturing-300`）。**未許諾の実名を slug に使わない。**

## ワークフロー

### A. 新しい事例を登録する

1. `cases/_template/` を `cases/cNNN-<slug>/` にコピー（番号は既存の最大 + 1）。
2. case.md のメタ情報を埋める（ステータス: 素材収集中、掲載許諾を必ず確認して記入。
   不明なら「未申請」として扱い匿名表記にする）。対応する Board 案件があれば
   **Board 案件番号**（数値 ID のみ）を記録する（下記「Board との紐付け」参照）。
3. `cases/README.md` の一覧表に 1 行追記、`cases/index.html` にカードを追記
   （ステータスバッジ: collect / drafted / ready / live）、`cases/index.json` に
   エントリを追加（tags は既存事例の語彙に揃える。新語彙の乱立を避ける）。

### B. 素材を追加する（随時）

1. テキスト素材は `inbox/YYYYMMDD-<内容>.md`、画像は `assets/` に置く。
2. **コミット前に許諾チェック**: 許諾ステータスが「実名許諾済」以外なら、
   素材内の顧客名・個人名・特定可能情報を属性表記（業種・規模・役職）に置換する。
3. 正本化はまとめてで良い。素材追加だけならここで完了。

### C. 正本化する（inbox → case.md）

1. `inbox/` の全素材を読み、case.md の各セクション
   （課題 / 決め手 / 施策 / 成果 / 声 / 媒体別の要点）に構造化して書き起こす。
2. 数値成果は出典となる inbox ファイル名を case.md 内にコメントで残す。
3. 「媒体別の要点」に、見出し候補（数値ハイライト）と媒体ごとに立てる要素を決める。
4. ステータスを「正本化済」に更新。掲載許諾とレビューが揃ったら「公開可」へ
   （文言のプロダクトオーナー承認ルールは docs/operations.md §4 に従う）。
5. 一覧 3 点（README.md の表 + index.html のバッジ + index.json）を更新。

### D. アウトプットを生成する（case.md → outputs/）

ステータスが「公開可」以降の事例のみ生成できる。媒体ごとの規範:

- **Web 用事例ページ** (`outputs/web/index.html`)
  - lp-create スキルの共通ルールに準拠（自己完結 HTML 1 ファイル・レスポンシブ・
    デザイントークン・アクセシビリティ）。トンマナは
    `.claude/skills/lp-create/tone-and-manner.md` に従う。
  - 構成: 表記名 + 数値ハイライト（hero）→ 課題 → 決め手 → 施策 → 成果 → 声 →
    プロダクト LP への CTA。画像は `../../assets/` を相対参照。
- **LP 組み込みパーツ** (`outputs/lp-embed/<name>.html`)
  - LP の事例セクションにコピペできる HTML 断片（`<section>` 単位、CSS 変数は
    LP 側のトークン名を使う）。声 1 本 + 数値 1 つ + 表記名に圧縮する。
  - 冒頭コメントに「正本: cases/cNNN-<slug>/case.md」と使い方を書く。
- **セールススライド** (`outputs/slides/`)
  - 1 事例 = 1〜2 枚。数値成果を最も大きく、課題 → 成果の対比 + 声一言。
  - .pptx で生成し、社内で編集して使う前提。ここに置く時点で公開されることに
    注意（スライドにも未許諾情報を入れない）。

生成後、ステータスを「掲載中」に更新した場合は一覧も更新する。

### E. 既存事例を更新する

- 内容の変更は必ず case.md → 各アウトプットの順で反映（正本先行）。
- 許諾ステータスが変わったら（例: 実名許諾が取れた）、表記名・slug の変更が
  必要か確認し、全アウトプットと一覧を再生成・更新する。

## Board（案件管理）との紐付け

案件管理システム Board（the-board.jp）の案件と事例プロジェクトは 1 対 1 で紐づく。

- 案件情報の取得は `scripts/board/board.sh` を使う（案件一覧 / 案件詳細 / 顧客一覧。
  セットアップと使い方は `scripts/board/README.md`）。
- 認証情報は環境変数 `BOARD_API_KEY` / `BOARD_API_TOKEN` またはリポジトリ直下の
  `.env`（gitignore 済み）のみ。**実値をリポジトリ内のファイルに書くことは絶対禁止。**
- リポジトリに記録して良いのは **Board 案件番号（数値 ID）のみ**。案件名・顧客名・
  金額・商談メモは商談情報のためコミットしない。API から取得した内容を事例素材に
  使うときは、掲載許諾ステータスに従って匿名化してから inbox / case.md に書き起こす。
- 「Board の案件 XXXX を参照して事例を作って」と依頼されたら:
  案件詳細を取得 → 許諾ステータスを確認 → 許諾範囲内の情報だけを
  ワークフロー A〜C の手順で書き起こす。

## 完了前チェック

- [ ] case.md のメタ情報（ステータス・許諾・最終更新日）が現状と一致している
- [ ] 許諾ステータスに反する実名・情報が、inbox 含めどのファイルにも無い
- [ ] Board の API キー/トークン、案件名・金額等の商談情報がどのファイルにも無い
      （書けるのは案件番号のみ）
- [ ] 数値・成果が inbox の素材と矛盾していない
- [ ] `cases/README.md` の一覧表・`cases/index.html`・`cases/index.json` の 3 点を更新した
      （index.json は `jq . cases/index.json` で構文チェック）
- [ ] HTML アウトプットは lp-create の checklist.md 該当項目（レスポンシブ・
      alt・コントラスト）を満たす
