# LP 制作スキル（デジタルワークス共通基盤）

このリポジトリは、複数プロダクト・複数訴求の LP を複数人（複数セッション）で
制作・蓄積するための共有ワークスペースである。LP に関する作業は必ずこのスキルの
手順とルールに従うこと。

## リポジトリ構造（正）

```
lp/
├── index.html                  # LP カタログ（一覧ページ）。LP 追加時に必ず更新
└── <product>/                  # プロダクト単位のディレクトリ（例: workmonitor）
    ├── README.md               # プロダクトの訴求サマリ（外部公開可能な内容のみ）
    ├── assets/                 # プロダクト共通画像（スクリーンショット等）
    └── lp00N[-x]/index.html    # LP 本体（連番 + バリアント接尾辞）
patterns/
├── README.md                   # デザインパターンカタログ（パターン追加時に必ず更新）
└── pNNN-<slug>/PATTERN.md      # パターン定義（構成・トークン・参照実装）
docs/operations.md              # 共同制作の運用ルール
```

## ワークフロー

### A. 新しい LP を作る

1. **プロダクトを確認する** — `lp/<product>/README.md` を読む。無ければ先に作る
   （ターゲット・ペイン・バリュープロポジション・キーメッセージ・CTA 方針を
   ユーザーにヒアリングして書き起こす。これが訴求コピーの正本になる）。
2. **パターンを選ぶ** — `patterns/README.md` のカタログから訴求・ターゲットに
   合うパターンを選ぶ。ユーザーの指定が無ければ候補を提示して選んでもらう。
3. **パターンを実体化する** — 選んだパターンの `PATTERN.md` を読み、
   「参照実装」の HTML をコピーして出発点にする。
   - デザイントークン（`:root` の CSS 変数）をプロダクトのブランドカラーに差し替える
   - コピー（文言）はプロダクト README の訴求内容から書き起こす。参照実装の文言を残さない
   - 画像は `lp/<product>/assets/` に置き、`../assets/...` の相対パスで参照する
4. **命名** — `lp/<product>/lp00N/index.html`。同一訴求のデザイン違いは
   `lp00N-b`, `lp00N-c` … と接尾辞を付ける（訴求が違うなら番号を進める）。
5. **カタログ更新** — `lp/index.html` に新 LP へのリンクを追加する。
6. **チェック** — [checklist.md](checklist.md) を全項目確認してから完了とする。

### B. 既存 LP を改修する

- 対象 LP の `index.html` を直接編集する。共通ルール（下記・トンマナ）は維持する。
- 大きくデザインを変える場合はバリアント（`-b` 等）として複製してから編集し、
  元の LP は消さない（A/B 比較のため）。

### C. 新しいデザインパターンを登録する

良いデザインの LP ができたら、再利用できるようパターンとして蓄積する。

1. `patterns/pNNN-<slug>/PATTERN.md` を作成（番号は連番、slug は英小文字ケバブ）。
   記載必須項目: **概要／適する訴求・ターゲット／セクション構成（順序と役割）／
   デザイントークン一覧／レスポンシブ方針／参照実装へのパス**。
   `patterns/p001-saas-zigzag/PATTERN.md` を雛形として同じ見出し構成で書く。
2. `patterns/README.md` のカタログ表に 1 行追加する。
3. 参照実装は `lp/` 配下の実 LP を指す（パターン側に HTML を複製しない。
   実装が更新されたら参照実装の指定も見直す）。

## 共通ルール（全 LP 必須）

1. **自己完結の静的 HTML 1 ファイル** — CSS/JS はインライン。外部 CDN・外部フォント・
   ビルド工程は使わない。画像のみ相対パスで参照可。
2. **`lang="ja"`**、`<title>` は「プロダクト名｜タグライン — カテゴリ説明」形式、
   `<meta name="description">` を必ず設定。
3. **レスポンシブ必須** — モバイル（〜560px）・タブレット（〜860px）・PC の 3 段。
   幅は `clamp()`、コンテナは `max-width` + `wrap` クラス。横スクロールを出さない
   （`overflow-x: clip`）。
4. **アクセシビリティ** — 全画像に具体的な `alt`、`width`/`height` 属性を付与。
   `prefers-reduced-motion` でアニメーションを無効化。コントラスト比を確保。
5. **デザイントークン** — 色は必ず `:root` の CSS 変数に集約し、直値を散らばらせない。
6. **CTA** — ヘッダー右上・hero・ページ末尾の最低 3 箇所。リンク先と文言はプロダクト
   README の CTA 方針に従う。
7. **事実性** — 数値・機能はプロダクト正本と矛盾させない。誇大表現・未確定の実績値・
   架空のお客様の声を書かない。料金表記はプロダクトごとの決定に従う。
8. **内部情報を書かない** — ビジネス戦略・転換率・収益構造などの内部文脈は
   LP にもこのリポジトリのドキュメントにも書かない（公開リポジトリのため）。

## トーン & マナー

文言・デザインの詳細規範は [tone-and-manner.md](tone-and-manner.md) を必ず読むこと。

[checklist.md](checklist.md) の全項目を確認し、ブラウザ実表示（またはスクリーン
ショット）で崩れが無いことを確認してから完了報告する。
