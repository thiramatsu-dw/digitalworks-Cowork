# トーン & マナー（全 LP 共通規範）

デジタルワークスが制作する全 LP に適用する。プロダクト固有の訴求・カラーは
`lp/<product>/README.md` が優先するが、ここに書かれた原則は上書きしない。

## 1. ライティング

### 声のトーン

- **平易・具体的・誠実**。専門用語より「時間とお金」「手間」の言葉で語る。
  業界用語を使う場合は直後に平易な言い換えを添える。
- 読者は忙しい意思決定者。1 文を短く、1 段落 3 文以内を目安にする。
- 煽らない。不安を突く場合も、必ず解決と前向きな未来をセットで提示する。
- 「〜できます」「〜が分かります」と読者主語のベネフィットで書く。
  機能名の羅列で終わらせない（機能 → ベネフィット翻訳を必ず行う）。

### 見出しの型

- hero 見出しは**対句・リズム**を意識した 2 行以内
  （例:「減らすのはムダ、増やすのはワクワク」）。
- セクション見出しは「読者の言葉」か「言い切り」。疑問形は課題セクションのみ
  （例:「こんな悩みは、ありませんか。」）。
- 各セクションに英字 eyebrow（ISSUES / FEATURES / FAQ 等）を付け、
  視線のリズムを作る。

### 数字の扱い

- 実数のある数字だけを使う（機能数・ステップ数・検知時間など）。
- 根拠のない導入実績・満足度・削減率を書かない。レンジ表現
  （「月 3〜7 時間」）は根拠がある場合のみ。
- 誤読を生む省略をしない（例:「測るのはムダ」単文は禁止 — 対句で使う）。

### 禁止事項

- 誇大表現（「業界No.1」「必ず」「絶対」）、架空のお客様の声・ロゴ
- 他社比較での名指し批判
- 監視・管理を連想させる表現をポジティブ文脈で使うこと
  （プロダクトによる。各プロダクト README の NG ワードに従う）

## 2. ビジュアルデザイン

### デザイントークン（構造）

全 LP は `:root` に以下の役割の変数を定義する。**変数名の役割体系を揃える**ことで、
パターン間の移植とレビューを容易にする。

| 役割 | 例（lp002 の値） | 用途 |
|------|------------------|------|
| プライマリ（濃・中・淡） | `--navy-deep` `--navy` `--navy-tint` | 見出し・ヘッダー・背景帯 |
| アクセント（グラデ 2 色） | `--amber` `--orange` | CTA・強調・アイコン |
| アクセント淡 | `--amber-soft` | 強調背景・チップ |
| 本文・補助文字 | 本文色 + `--ink-sub` | テキスト階層 |
| 罫線・紙色 | `--line` `--paper` | カード枠・セクション背景 |

- 色はトークン経由でのみ使う。1 ページのアクセント色は 1 系統（グラデ 1 種）に絞る。
- プロダクトごとにプライマリ／アクセントを差し替えれば、同じパターンで
  別ブランドの LP が作れる状態を保つ。

### タイポグラフィ

- フォントスタック: `"Hiragino Kaku Gothic ProN", "Hiragino Sans", "Yu Gothic", "Meiryo", sans-serif`
  （外部 Web フォントは使わない）。
- 本文 `line-height: 1.85` 前後、見出し `1.4〜1.65`。
- 見出しサイズは `clamp()` で流動化（例: `clamp(22px, 4.6vw, 34px)`）。
- 太字階層: 見出し 800 / 強調・ボタン 700 / 本文 400。

### レイアウト

- コンテナ最大幅 1120px 前後、左右パディング `clamp(16px, 4vw, 32px)`。
- セクション上下余白は `clamp(56px, 8vw, 104px)` 級。詰めすぎない。
- 明（白・紙色）と暗（プライマリ濃色）のセクションを交互に置き、
  ページに緩急を作る。暗セクションは 1〜2 箇所まで。
- カードは `border-radius: 14〜18px`、控えめな `border` + 大きく柔らかい `box-shadow`。

### モーション

- アニメーションは装飾 1〜2 種まで（浮遊カード等）。`prefers-reduced-motion: reduce`
  で必ず無効化する。
- ホバーは `transform: translateY(-2px)` + シャドウ強化程度に留める。

### 画像・スクリーンショット

- プロダクト画面は「ブラウザ風フレーム」（ドット 3 つ + アドレスバー）に入れて
  実画面であることを演出する。
- スクリーンショットは実画面 or デモデータ画面のみ。デモデータの場合はキャプションに
  明記する。1 枚 600KB 以下を目安に圧縮する。
- `alt` は「何の画面で何が見えるか」まで書く（SEO とアクセシビリティ両方のため）。

## 3. 構成の基本骨格

パターンにより並びは変わるが、以下の要素を基本セットとする:

1. **ヘッダー**（ロゴ + アンカーナビ + CTA ボタン、sticky）
2. **hero**（ターゲット明示 pill → 対句見出し → リード文 → CTA → 信頼要素 3 点）
3. **数字/実績バンド**（プロダクトの事実数字 4 つ程度）
4. **課題**（読者のペインを 3 つ、読者の言葉で）
5. **解決・提供価値**（ソリューションの構図、導入フロー）
6. **機能詳細**（ベネフィット翻訳付き）
7. **信頼・安心**（セキュリティ、プライバシー、導入のしやすさ）
8. **FAQ**（想定される不安を先回りで 3〜5 問）
9. **CTA セクション**（行動障壁を下げる一言 + ボタン）
10. **フッター**（提供会社表記: 株式会社デジタルワークス で統一、住所、コーポレートサイトリンク）
